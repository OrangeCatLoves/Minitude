# Minitude: notes for Claude Code

Pixel-art browser trivia game. Seven prompts per run, the player types any valid answer, rarer answers score more and shrink the player further (1.7 m down to the Planck length). This repo is **Phases 1 to 3: the playable solo game, a SQLite database, an answer checker, an offline question generator, a server-side question clock, multiplayer rooms, and the Daily Challenge (same seven questions for everyone each UTC day, one attempt, guests only) with Fly.io deployment files.** The game was deployed to Fly.io on 5 November 2026 as `minitude-lwb` (Singapore; `docs/DEPLOY.md`). **On 14 November 2026 a seventh rarity was added: SINGULARITY, the hidden gem (120 points, a rainbow Crescent, one per question, kept in a cabinet in the player's browser; LIVE on Fly since 14 Nov 2026): see the rules below, `docs/DECISIONS.md` and `docs/SERVER.md` (Gems).**

**Since 12 November 2026 the live game uses NO language model** (the owner's decision): answers are checked against answer lists built ahead of time (stored answers, their aliases, other ways of writing them, and slips the player is asked about); an answer that is not on the list is rejected; rarity is stored with each answer and set offline. The Gemini code (`src/llm/`, the model branch of `judge/pipeline.ts`, `src/generate/`) is kept only for the optional offline question generator and the old tests; `test/nomodel.test.ts` fails if the server's start-up code or routes reach it. Answer lists are grown with `src/expand/build.ts` (from Wikidata), hand-written lists in `data/curated/`, `data/group-terms.json`, and `answers add / alias / unknown / lint / import-expansion / import-groups`: read `docs/ANSWER_LISTS.md`.

Read first: `docs/STATUS.md` (what is done / not done), `docs/SERVER.md` (database, answer checker, generator, clock, the Daily, commands), `docs/DECISIONS.md` (choices made without asking), `docs/DEPLOY.md` (Fly.io), `docs/BANK_SHEET.md` (the page that lists every question and answer, and how to keep it current), `docs/SITE.md` (the page under the end-of-run report, the privacy page and its contact details; live since 13 Nov 2026), `docs/SECURITY.md` (what anyone on the internet can reach, the attacks tried on 16 Nov 2026 and what stops them, what is left, and the accounts the owner should protect), `docs/PROJECT_CONTEXT.md` (the full planning notes; the end of the file says what Phases 1 to 3 cover), `docs/GROWTH_TO_1000.md` (the plan and the numbers for going from 500 to 1,000 questions: disk, bank sheet, categories, pace; 18 Nov 2026, not yet decided).

## Commands

```bash
npm install
npm run dev          # API on :8787, game on :5173 (Vite proxies /api)
npm test             # core, web (camera) and server unit tests
npm run typecheck    # all three packages
npm run build        # typecheck + build packages/web/dist
npm start            # one process, game + API on :8787 (needs a build)
npm run trial -w @minitude/server -- --generate   # the OLD live Gemini trial (not used by the game any more; needs a key)
npm run cli -- traffic  # visits, finished solo runs and Daily players per day, and where visits come from (docs/TRAFFIC.md)
npm run cli -- help  # questions, answers (unknown, add, alias, import-expansion), gems (list, set, clear, import, audit), daily sets, db backup, the question generator
npx tsx packages/server/src/expand/build.ts --out <folder>      # offline: build answer-list expansion files from Wikidata (read-only on the database)
npx tsx packages/server/src/expand/evaluate.ts                  # offline: replay the test cases on a COPY before/after an expansion
fly deploy --ha=false  # see docs/DEPLOY.md (first run 5 Nov 2026, app minitude-lwb)
```

Node 20+. No other setup. Never commit keys: the server reads `DATABASE_FILE`, `PORT`, `DAILY_PER_IP`, `MAX_RUNS_PER_DAY` (new solo runs a day for the whole server, default 20,000, 0 = no limit), `CLIENT_IP_HEADER`, `BACKUP_DIR`, `BACKUP_KEEP` from the environment or from `packages/server/.env` (git-ignored; copy `.env.example`). `GEMINI_API_KEY`, `LLM_MODEL` and the other `LLM_*` settings are read only by the command line (the optional question generator): the running server ignores them. There is no `GEMINI_API_KEY` secret on Fly any more (removed 12 Nov 2026; Fly has no secrets set).

## Layout

## Rules that are decided. Do not change them without asking the owner

- 7 prompts per run. Tiers: **Common 20, Uncommon 30** (an Uncommon answer is exactly one world), Rare 40, Exotic 60, Legendary 80, Mythic 100, and **SINGULARITY 120 (the gem)** (Common was 10 and Uncommon 20 until 18 Nov 2026: the owner stretched the worlds over 0 to 600 points and wanted two Common answers to always reach the next world). The most a run can score is **840** (the report says "/ 840 points"); seven Mythic answers are still a perfect run (700), and a gem keeps a run perfect. Planck Foam needs 700, so only seven Mythic answers (exactly 700) or a run with gems reach it.
- **Gems (SINGULARITY, chosen by the owner 14 Nov 2026).** Every approved question has exactly one gem: one very obscure answer (stored Mythic; the owner's one exception is Tonkotsu ramen for "Name a soup", stored Legendary) that scores 120 and shrinks the player by 10,000 (the stamp "÷ 10,000"; it was 1,000,000 until 18 Nov 2026, when worlds became 30 points wide and the owner accepted ÷ 10,000). It is NOT a stored tier: `answers.tier` stays 0 to 5 (the database `CHECK` would need a table rebuild), the `gems` table (migration 4) names the question's gem answer, and the answer checker reports tier 6 for it (every spelling, alias or confirmed correction of the gem counts). The 500 gems (200 from 14 Nov, 50 more with Batch 5 on 16 Nov, 100 more with Batches 6 and 7 on 17 Nov, 150 more with Batches 8 to 13 on 18 Nov) and their one-line descriptions are in `packages/server/data/gems.json` (import with `gems import`, check with `gems audit`); a NEW question needs a gem too (`docs/ANSWER_LISTS.md`). The gem picture is the rainbow Crescent (Twilight tone), `packages/web/public/assets/gem6.png`; the 61 other designs the owner saw are kept in `drafts/draft-singularity-gems/` for reference. Found gems are kept only in the player's browser (`minitude.gems`, the privacy page says so); no gem name or description is ever sent before the player has answered, and the cabinet shows hidden slots as counts only (`GET /api/gems`: counts per category, no prompts, no answers). Do not change the points, the 840, the gem count per question or the Crescent without asking.
- **Scoring and size (changed by the owner on 18 Nov 2026, "I want unexplored at 600-700 and Planck at 700. 10,000 is acceptable").** Size = 1.7 m / 10^(points / 30) inside worlds 1 to 20 (`POINTS_PER_WORLD` in `packages/core/src/scoring.ts`): every world is 30 points and still exactly one power of ten, so each world's picture and honesty label stay true (world 20, "the LHC reaches this small", ends at 600 points and 1.7 x 10^-20 m). **Unexplored = 600-699 points** (its 15 dark pictures spread over 100 points, one every 6.67 points). **Planck Foam (world 21) starts at 700** (`PLANCK_POINTS`; it was 555 from 16 Nov 2026 and 440 before); the finale plays the moment the total crosses 700 and points above still count. Seven Mythic answers make exactly 700 (report: "About one Planck length."); six Mythic and a Legendary is 680, short. Unexplored is only 100 points wide, so a gem from the end of world 20 (580 to 599) skips it and lands in Planck Foam, and so does a Mythic from exactly 600. The stamps shown with a dive are the tier's own, rounded: Common ÷ 5, Uncommon ÷ 10, Rare ÷ 20, Exotic ÷ 100, Legendary ÷ 500, Mythic ÷ 2,000, SINGULARITY ÷ 10,000. The points are stored with every answer, so migration 6 rescaled the answers already stored (Common 10 to 20, Uncommon 20 to 30) and re-added the Daily totals. The 36 picture slots and all 15 dark pictures are unchanged.
- Edging hint: 2nd landing in a row inside Unexplored shows "Something is getting closer.", 3rd or more "It is very close."; the 1st keeps the Unexplored card. A run ending in Unexplored says "Planck Foam was N points away".
- After the finale: 1st answer shows one of three lines at random (never the same as last time) plus the small line "Our physics stops here. Keep going."; the 2nd shows "There is nothing left to measure you with." / "You are still shrinking.". Report says "N points past the edge".
- Each hint is one text line, one glow pulse, one sound. No extra cards.
- No language model in the live game (12 Nov 2026, chosen by the owner): answer lists are built ahead of time; an answer not on the list is rejected ("We don't have that one. Check the spelling or try another."); rarity is decided offline and stored with the answer. Real answers must be accepted as far as possible by growing the lists (aliases, Wikidata expansion, `answers unknown` to see what players typed), not by a model.
- Group names count: an umbrella term where every member would be valid ("rattlesnake", "viper" for venomous snakes) is accepted as Common (tier 0), whatever the question's rules say. The question's own subject word ("snake") and terms that include invalid things do not count. Chosen by the owner. With no model this is DATA: such terms must be added to the lists as answers or aliases (tier 0); the old wording in `judge/prompt.ts` is no longer used live.
- Corrections need consent: a misspelling is never accepted on the spot. The game asks "Did you mean X?" (YES / NO); the question clock keeps running while it asks. No means the text is judged as typed, never as the suggested answer. Chosen by the owner; see `docs/SERVER.md`. Matching is generous (`typoBudget`: none up to 3 letters, 1 up to 7, 2 up to 11, 3 beyond; a swapped pair of letters is one slip; aliases are matched too) BECAUSE a wrong guess only costs one key press. A different way of writing the same answer (a hyphen or space, British spelling, Roman or Arabic numerals, "Mt" for "Mount") is not a misspelling and is accepted at once (`looseKey`). OCCASIONAL SURPRISES ARE WANTED (owner, 12 Nov 2026): a text a couple of slips from a real answer, even one the player did not mean (typing "Mekong River" and being asked "Did you mean Moa River?" because the Moa is also called the Makona), is a small delight, not a bug. Do NOT tighten the matching to remove them (a word-by-word rule that did was tried and reverted). Only texts far from every real answer must never match. If the owner ever wants silent autocorrect instead (generous autocorrect sometimes produces "weird matches"), ask first.
- Players are never told how answers are checked: no model name, nothing about lists, mock or real, in any API reply, message or browser code (tests guard this). The server's own logs and database may record it. Chosen by the owner. **One exception, also chosen by the owner (14 Nov 2026): after finishing a Daily, the player can see every answer that was accepted for each of its questions, by rarity** (see the next rule). That shows WHAT counts, never HOW it is checked; the wording must stay free of "list", "checker", model names and the like.
- **"Everything that counted" (14 Nov 2026, the owner: "I don't want the answers to be a mysterious black box").** On the Daily's end-of-run report (also today's result opened from the title) every row opens a screen with how many accepted answers each rarity holds, the names (a rarity at a time, A to Z, 100 more on request, with other accepted spellings), a search across all of them, and the question's SINGULARITY gem (revealed there). It is shown straight away to the player who finished that Daily (the owner accepted that early finishers could share answers or replay with them); **since 18 Nov 2026 (the owner: "do the same for solo run as well" and for multiplayer) the same screen opens from the solo run's report and from the multiplayer final screen too:** a solo run once all seven questions have a result (`GET /api/run/:id/answers` and `/list`; the run id is a random UUID that only that browser holds), a multiplayer match once it is over and only for a player in that room (`GET /api/versus/:code/answers` and `/list`; 409 `not_over` before, 404 for anybody else; closed again by a rematch). The server only answers a guest who has FINISHED that day's Daily (`GET /api/daily/answers`, `/api/daily/answers/list`: 403 before, 404 for another guest or day), the gem is counted under SINGULARITY and not under its stored rarity. Do not widen it any further (before the run or match is over, or to people who did not play it) without asking.
- Daily: resets at midnight UTC; guests only (a random id in the browser, no sign-up); mixed categories; hosting is Fly.io. Chosen by the owner.
- Interface is the v5 video's: minimal, "WORLD n / 21", no fun facts, world title cards skip on tap, 30 s per question.
- **Ads: only the layout exists, SWITCHED OFF (`ADS_ENABLED = false` in `packages/web/src/ads.ts`; the owner's choices of 17 Nov 2026, `docs/ADS.md`).** On the game page ads may only ever be on the TITLE SCREEN: a large monitor (about 1500 px wide and up) gets a left ad, a right ad and a bottom banner, anything smaller gets one 320 x 50 banner at the very bottom, and a phone on its side gets none; EVERY ad is kept 150 px from the game and its corner buttons (Google's guidance for games; the owner chose "no risk of a violation notice"), so the game is smaller on the title screen; there is also one ad place on each of the text pages (how to play, about; none on privacy); nothing during a run, in the lobby, on the report or the finish screen, nothing over the gem cabinet, never hold PLAY back for an ad, and NO full-screen or floating formats. Do not widen it without asking the owner. Money is the owner's stated priority; traffic (about 0 to 3 Daily runs a day on 16 Nov) is the bottleneck, not the network.
- **The world pictures move a little ("living worlds", chosen by the owner, 16 Nov 2026).** The owner reviewed drafts over five rounds and picked one design of three for each world from 7 on: 7A, 8A, 9C, 10B, 11C, 12A, 13C, 14C, 15B, 16A, 17A, 18C, 19C, 20A, Planck Foam A (`drafts/draft-world-motion/README.md`; worlds 1 to 6 and Unexplored have one design each). ## Working in this code

- Do not change the maths in `timeline.ts`, `finale.ts` or `audio.ts` casually: they are ports of the video's Python (`tools/art-source/engine-prototype`), and `docs/ENGINE.md` names the Python function each one came from.
- The living worlds: a frame of a world picture is a pure function of (slot, seconds since the camera arrived, amount of life); amount 0 must give the original picture exactly, and `packages/web/test/life.test.ts` compares every world with the frames the owner reviewed. `life/engine.ts`, `designs.ts`, `artsource.ts` and `light.ts` are the reviewed JavaScript carried over (`// @ts-nocheck`): change a world in `drafts/draft-world-motion/src` first, carry it over, take new fingerprints with `node drafts/draft-world-motion/tools/golden.cjs`. If a world picture is redrawn, its movement must be looked at again.
- Test visual or timing changes with `tools/browser-test` (`?manual=1` lets a script step the clock and screenshot any instant). The headless browser draws WebGL in software, so a real-time run there looks laggy; that is not a bug.
- Scoring or hint changes: edit `packages/core` and its tests first; the game and server read from it.
- Keep answers out of the browser until the player has answered (the API never sends them; there is a test for it; the same goes for the gems: nothing says which answer is a question's gem until it is found). Keep prompts out until their question starts (`POST /api/run/:id/start` is the only way to get one; also tested).
- A daily set is written once and never changed after somebody has played that day. Never log or store a raw network address: only the day-bound hash.
- Run exactly one server process and one machine; SQLite lives on one disk.
- Schema changes: add a NEW entry at the end of `MIGRATIONS` in `db/schema.ts`; never edit an old one.
- `normalize()` produces the stored keys (`answers.norm`, `spellings.norm`): changing it means re-keying the database. New ways of treating text go in `looseKey` / `match.ts`, which are computed at lookup time and never stored.
- Tests use `testRepo()`, `FakeLlm` and a fake clock (`test/helpers.ts`); nothing in the unit tests touches the network or a real database file.
- A decided rarity is stored per canonical answer: do not re-score stored answers on every request. Corrections go through `answers set-tier` so they are logged.
- **Keep the bank sheet current (owner's standing request, 12 Nov 2026).** There is one published, searchable page with every question and answer (live, draft, rejected): `docs/BANK_SHEET.md` has the link and the two steps (`tools/bank-sheet/refresh.ps1`, then publish `list-build\sheet\bank-sheet.html` again with the same file path so the link stays). Do this whenever questions or answers change: a new batch drafted, a draft approved or rejected, answers added or removed, an expansion imported, a tier fixed, a deploy that changes the bank. - **Keep the privacy page true** (`packages/web/privacy.html`, `docs/SITE.md`). It tells visitors there are no cookies, no analytics or third-party scripts, Cloudflare for DNS only, typed answers kept for solo and Daily runs but not multiplayer, and what ratings and ideas keep. If a change makes any of that false (analytics, cookies, proxying through Cloudflare, storing new personal data), change the page and its date in the same change. It must never say how answers are checked (`packages/web/test/private.test.ts` scans it).
- **Keep the doors shut (security, 16 Nov 2026; `docs/SECURITY.md`).** The API reads a request body only up to `MAX_BODY_BYTES` (8 KB): a bigger body is refused before it is read (80 MB once took the server from 83 MB to 2.3 GB of memory). There is no CORS header on purpose (only the game's own pages call the API). Addresses are counted per network (`networkOf`: an IPv6 visitor is their /64), and new solo runs are capped per day and refused when the disk is nearly full. Every reply carries a Content-Security-Policy that allows only the site's own address (`src/securityHeaders.ts`); a new feature that needs an outside host or an inline script must change that policy on purpose, with `tools/browser-test/csp.cjs` passing. Text that comes from visitors goes through `tidyTyped` before it is stored (the owner reads it in a terminal). Never build HTML from text in the browser (no `innerHTML`).
