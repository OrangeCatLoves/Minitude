# Answer lists: how they are built and grown (since 12 Nov 2026, no model in the live game)

The live game accepts an answer only if it is on the question's list (see `docs/SERVER.md`, "How an answer is judged"). So the lists have to be as complete as we can make them. They are grown offline, and nothing reaches the live site without running a command.

## What the player experiences
- Exact answer, an alias, or the same answer written another way (hyphen/space, British spelling, Roman numeral, "Mt" for "Mount"): accepted at once.
- A slip (swapped letters, a missing or wrong letter; a wrong first letter counts double): "Did you mean X?" The player says yes or no.
- Anything else: "We don't have that one. Check the spelling or try another." The text is kept with the attempt.

## The loop that makes the lists better
1. `npm run cli -- answers unknown` shows what players typed that was not found, most often first. If it is valid: `answers add <question-id> "<name>" <0-5> --alias "..."`, or `answers alias <question-id> <answer> "<other way to write it>"`.
2. `npm run cli -- answers lint` lists pairs of different answers that are one slip apart. A pair is a warning: a typo near both would be ambiguous, and an alias one letter off an unrelated phrase is how odd corrections happen (krillion's FAQ admits this happens to them).
3. `npm run cli -- answers list <question-id> --source wikidata` (or `--source curated`) shows what the builders added, to vet.

## Growing the lists in bulk (offline, uses the internet only for Wikidata)
- `npx tsx packages/server/src/expand/build.ts --out <folder>` asks Wikidata (public-domain data) for everything in the class each question is about (venomous snake species, apple cultivars, pharaohs, volcanoes, airlines ...) and writes ONE review file per question: new answers with a tier, and other names for answers we already have. It only READS the database. `--only <question-id>` does one question; `--cached` redoes the merging from what was fetched (kept in `<folder>/raw`) without asking Wikidata again.
- **How a tier is chosen** for a new answer: how many Wikipedia languages know the thing (Wikidata "sitelinks"; for World Cup teams, the number of tournaments), compared with the answers that question already has. The question's own tier counts are laid over its answers in order of how well known they are, and a new answer takes the tier of the place it would stand in (less known than all of them: the rarest tier). The file records the rank correlation between "how well known" and the existing tiers (`rankCorrelation`): about -0.8 for airlines, pharaohs and constellations (good), about -0.4 for programming languages and apples, -0.1 for rivers and warship types (weak: check those tiers).
- `data/curated/make-curated.cjs` writes hand-written lists for questions Wikidata cannot cover (kitchen junk drawer, wall-outlet items) and a Smash fighter roster. `data/group-terms.json` holds the group names that count as Common ("viper", "bear" ...).
- `npm run cli -- answers import-expansion <file or folder> [--dry-run]` adds a review file (a folder: every .json in it). `answers import-groups` adds the group names. Both only ADD, never change or remove, and skip anything a person ruled out. Added answers get `source = wikidata` or `curated`.
- To undo an import: `DELETE FROM answers WHERE source IN ('wikidata','curated')` removes the answers and their aliases go with them (foreign keys cascade).

## New questions: building a batch and putting it live (Batch 1, 30 questions, done 12 Nov 2026)

**Building** (`src/expand/newq.ts`, recipes in `src/expand/batch1.ts`; one recipe per question, a Wikidata class plus a hand-written `mustHave` list):
`npx tsx src/expand/newq.ts --batch batch1 --out C:/Users/weibi/minitude/list-build/batch1 [--cached] [--only <id>]` writes `bank.json` (drafts), `review.md` (the sheet to vet) and `raw/` (what Wikidata returned; `--cached` rebuilds from it in seconds; delete one `raw/<id>.json` to fetch just that question again). It ends with a self-check on an in-memory database.
- Rarity is cold-start: rank within the class, about 10 Common, 20, 40, 80, 160, the rest Mythic. `mustHave` (the answers a casual English-speaking player thinks of first, most obvious first) rank strictly in that order above everything else; one the class lacks is added by hand and flagged on the sheet.
- Traps found: (1) Wikidata keeps a name that is the same in most languages (The Godfather, Tetris, Tyrannosaurus) ONLY under the "mul" label, so a label query must take English else mul (`detailsOf`); asking for English alone silently drops the best-known items. (2) One big id query comes back incomplete (9,034 films in bands, 8,152 in one query), so `idsInBands` fetches by number of languages and splits a band that is big or fails. (3) Many famous items are an instance of a SUBclass (animated film, international airport, animated television series), so look at what the famous ones are an instance of before choosing the class. (4) A query that is too heavy (every band of any rock genre) just never answers: after about 8 minutes, stop and use the plain class plus `mustHave`. (5) A skip filter for "Association" or "League" also drops "association football" and "rugby league": hand-listed answers are exempt from `skip`.

**Putting a batch live** (rehearse on a copy first; needs the owner's explicit go):
1. Rehearse: copy a fresh snapshot of the live database (`tools/bank-sheet/refresh.ps1` leaves one at `list-build\sheet\live-snapshot.db`), then with `DATABASE_FILE=<copy>`: `questions import <bank.json> --approve`, `daily clear <each planned day nobody has played>`, `daily plan --days 7`, `daily show <day>`. Also run the import with `NODE_OPTIONS=--max-old-space-size=80` to prove it fits the 256 MB machine.
2. Fly: `db backup /data/backups`; `flyctl ssh sftp put <bank.json> /data/batchN-bank.json`; `NODE_OPTIONS=--max-old-space-size=100 ... cli.ts questions import /data/batchN-bank.json --approve` (the cap makes a too-big import stop itself instead of squeezing the server); then `daily clear` for every planned day that nobody has played and `daily plan --days 7`. A day somebody has played cannot and must not be changed (on 12 Nov that was today's set).
3. Check: `/api/health` shows the new question count on minitude.io, `db stats`, server memory in `/proc/<pid>/status` (61 MB after Batch 1), `flyctl status`.
4. Refresh the bank sheet (`docs/BANK_SHEET.md`).
- Result: 22 to 52 approved questions, 19,429 to 78,938 answers, 22,135 to 87,765 spellings; the database grew from 6.9 MB to 21 MB; the planner puts never-used questions first, so the first four new Daily days were all new questions.
- Not done after Batch 1: a live player-path check of a new question (the same answer checker was run on a copy: JFK, LHR, Heathrow, SIN accepted). Short forms such as "Changi" or "Kennedy" on their own are not accepted for airports; the owner said that does not need fixing.

**Lessons (they apply to every future batch):**
1. **Wikidata files things by "facet", not always by the class you expect.** Before writing a recipe, look at how a FAMOUS example is filed (`P31`, and the statements next to it). Found this time: famous diseases are "type of disease", medicines are found by their full 7-character ATC code (`P267`), novels carry `P7937` "form of creative work = novel" (their `P31` is just "literary work"), superheroes are characters with the occupation (`P106`) "superhero", game consoles are SUBCLASSES (`P279`) of "video game console" (their `P31` is "product model"), and people are found by occupation (`P106` with a short `VALUES` list; walking every subclass of "scientist" is far too heavy). The first run of 5 questions got 3 to 36 answers from Wikidata until their class was fixed.
2. **A famous name that exists only as an ALIAS of a related item must get an answer of its own.** "Toyota Corolla" was an alias of "Toyota Auris", "Zoom" of "GitLab", "Captain America" of "Bucky Barnes". Add it as an `extras` entry (an answer of its own beats the alias); use `rename` only when the two really are the same thing (spinach and "Spinacia oleracea", lychee and "litchi"). The review sheet now flags every "LISTED NAME LANDED ON AN ITEM WITH ANOTHER NAME" so a person can check.
3. **Hand-listed answers are exempt from the generic-word filter and from `skip`.** (The Batch 1 filter had silently dropped "Dog", "Horse" and "Shark".) A hand-added answer also wins a name tie with a Wikidata item that reads the same ("Google" and the old "Google+": the text matching ignores the "+").
4. **Wikidata can be vandalised, and an answer list inherits it.** The English label of the dinosaur Compsognathus read "messielgoat" in November 2026 and went into a live question. Run `npx tsx src/expand/labelcheck.ts <batch folder>` on every batch: it lists best-known answers whose English label has nothing in common with their language-neutral label, for a person to read. Batch 2 was clean (two cases, fixed with `skip` and an extra); a label that is only a Wikidata code is now treated as missing, and a name or alias that is a bare code is dropped.
5. **Scientific names** (the animal rules accept them) are added as aliases for the 600 best-known species of each animal question, from the item's language-neutral label when it is a Latin name (`addScientificNames`, cached in `scientific-names.json`). Other language-neutral labels are NOT used as aliases: they can be a native-language name or, now and then, nonsense ("pornografia" for a war).
6. Surnames are accepted for people (`personForms`: "Messi" for Lionel Messi), "Mount Everest" also as "Everest", and so on (`alsoWritten`); where two people share a surname the better-known one gets it.

**More lessons (7 to 13, found while building Batch 3; the Batch 2 cleanup used them):**
7. **Preflight every recipe before the long fetch.** Fetch only the best-known band (12+ languages) and count how many of the first 14 hand-listed names it finds; under about 8 of 14 means the class is wrong. It caught: famous flowers (filed as a colour or a plant taxon: replaced by deserts), operas and musicals (Wikidata has ONE class, "dramatico-musical work": merged into one question), technology companies (Amazon, Intel and Nvidia are filed by industry, `P452`, not as "technology company"), phones (smartphone model series and "cell phone model"), game shows (genre `P136`). It takes about 3 minutes for all 50.
8. **"Video game series" misses most famous series** (Final Fantasy and Call of Duty are filed as "media franchise"). The GAMES know their series (`P179`): taking every item that a video game points to found 32 of 40 famous franchises against 19.
9. **People found by occupation include everyone who ever had it, and fictional characters.** Samuel Beckett is a "cricketer", George H. W. Bush, Bing Crosby and Michael Jordan are "baseball players", Wonder Woman is an "astronaut", and Wikidata calls the Pope and the French President (Co-Prince of Andorra) "monarchs". Their fame pushed them into tier 2 above real players. Fix used for all the person questions: humans only (`?item wdt:P31 wd:Q5`), keep a person only if Wikidata's one-line description names the activity (`notDescribedAs(/baseball|pitcher|.../)` in `recipes.ts`, which uses `Candidate.desc`; a hand-listed name is never dropped), and for monarchs leave out the three positions (`FILTER(?pos NOT IN (...))`). Requiring the `sport` statement (`P641`) was tried and did NOT help: the same people have it.
10. **Subclasses leak.** Game consoles came in under "toy", tacos and burritos under "sandwich", individual meteorites and concrete under "rock", monuments (Stonehenge, the Colosseum) under "museum", tube stations under "railway station", Latin-named plant taxa and salt under "herb or spice". Read tiers 0 to 2 and a tail sample of every question in `review.md` after the build and add a `skip` (names, or the description) or a `FILTER NOT EXISTS` to the query; it took two rounds.
11. **Check the display name of the best-known answers.** Wikidata labels the Komodo dragon "Ora" and the bearded dragon with a slur-like Australian nickname ("Jew Lizard"). `rename` shows the listed name, and `UNWANTED` in `newq.ts` makes sure the slur is never stored, even as an alias (a test covers it). A scan of every raw file for slur-like words found nothing else that was not a place or species name (Negros, Oriental, Savage's, Negroamaro); the candy named "Negro" and "Midget Gems" were skipped.
12. **Wikidata does not hang snakes, lizards and turtles under "Reptilia"** (its children are mostly fossil genera). Reptiles start from the four living orders (Squamata Q122422, Testudines Q223044, Crocodilia Q25363, Rhynchocephalia Q15099738).
13. **"From narrative universe" (`P1080`) is a list of everything in a fictional universe** (levels, power-ups, places). For Mario characters keep only the character-like classes (`VALUES ?k {...}` in the recipe): 22 answers became 117.

**Found in the LIVE Batch 1 questions by `labelcheck` on 13 Nov 2026 (not fixed, waiting for the owner):** four junk answers, all vandalised or mistyped Wikidata English labels: in "Name a dinosaur", `messielgoat` (Compsognathus, which is also there under its real name), `Mussaurdes` (Mussaurus) and `Gordosaurus` (Gorgosaurus); in "Name a car brand", `Maḥmīyat Umm al-Rayḥān` (an Arabic-script label). ## Every new question needs a gem

Since 14 Nov 2026 each approved question has one gem (a very obscure answer, scoring 120). When a batch of questions is approved, pick one very obscure real answer for each (known in few Wikipedia languages; read its Wikipedia article before writing its one-line description), add them to `packages/server/data/gems.json`, then `gems import --dry-run`, `gems import` and `gems audit`. **More lessons (19 to 25):**
19. **A genre tag leaks the neighbouring genres.** Games tagged strategy included RPGs and shooters, crime series included superhero shows, action films included animated films. Read tiers 0 to 2 and add `skip` names; for films `FILTER NOT EXISTS { ?item wdt:P31/wdt:P279* wd:Q202866 }` removes animated ones.
20. **A cuisine query must also require the item to be a dish** (`P31/P279* Q746549` or `P279+`). Otherwise ingredients, techniques and products leak in (Sichuan pepper, wakame, Nutella, "sautéing"). Pastries (`Q477248`) leaked even harder (waffles, hot dogs, pies) and were replaced by salads.
21. **Hand-listed names are exempt from `skip`:** do not put a name in `mustHave` that a skip filter should drop (Brownie and Muffin in cakes, Cars and Rocket League in racing games).
22. **Some classes cannot work:** "sculpture" brings coins, banknotes and landmarks (use "statue" and hand-list the famous sculptures); "road" brings streets, squares and bridges; "comic book series / comic strip" returned comic CHARACTERS; "star" times out; racehorses and trains are thin and mixed. Preflight and a look at the best-known band (`topnames.mts`) catch them before the long fetch.
23. **Check what a Wikidata alias lands on.** Read every "LISTED NAME LANDED ON AN ITEM WITH ANOTHER NAME" flag: some are different things (a Polish upland as "Jura Mountains", other species as "Irrawaddy dolphin"). Give the real answer an `extras` entry.
24. **Gems: check each one against the question's rules and its Wikipedia article.** An automatic pick of the least-known Mythic answer found a science-fiction film for the action question and a show tune for a Rolling Stones list. Require a keyword in the article (`REQUIRE` in `gems5.mts`) and read the 50 by eye.
25. **The slur guard must match inside longer words** (a film title with the word fused to another).
